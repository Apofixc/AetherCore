# 📊 Сайзинг ресурсов и методология профилирования

## 1. Рекомендации по аппаратному обеспечению (Hardware Sizing)

Платформа **Next-Gen Universal Core Platform** скомпилирована в нативный машинный код на Rust и использует архитектуру асинхронного ввода-вывода Tokio с Wasmtime Component Model.

### Расчет ресурсов под масштаб развертывания:

1. **Базовое потребление ядра**:
   - Размер бинарного файла `nms`: ~15–20 MB (release build с LTO).
   - Базовая оперативная память (RSS) при старте: ~12–25 MB (включая SQLite WAL пулы, реестр i18n и Axum роутер).
   - Каждое активное WebSocket соединение: ~5–10 KB памяти.

2. **Память гостевых WASM плагинов**:
   - Память инстанса Wasmtime: настраивается через `memory_limit_mb` (по умолчанию 32–128 MB на плагин).
   - Общая требуемая память: `RAM = Base_Core (64MB) + N_Plugins * Avg_Plugin_RAM + Active_WS_Connections * 10KB`.

3. **Дисковая подсистема и SQLite WAL**:
   - База данных работает с постраничной записью (4 KB page size).
   - При активной записи журнала событий (`event_journal`) рекомендуется использовать твердотельные накопители (NVMe/SATA SSD) с поддержкой параллельных операций чтения.
   - Размер WAL-файла автоматически ограничивается периодическим чекпоинтом (`PRAGMA wal_autocheckpoint`).

## 2. Методология нагрузочного тестирования и профилирования

Для проведения верифицированных замеров производительности в целевой инфраструктуре используется следующий стандартизированный протокол:

### А. Тестирование пропускной способности HTTP API:
```bash
# Использование утилиты wrk для замера RPS эндпоинтов ядра
wrk -t4 -c100 -d30s http://127.0.0.1:8080/health
wrk -t4 -c50 -d30s -H "Authorization: Bearer <token>" http://127.0.0.1:8080/api/v1/modules
```

### Б. Профилирование памяти и CPU:
- Использование `heaptrack` или `valgrind --tool=massif` для анализа аллокаций памяти.
- Мониторинг системных метрик через Prometheus эндпоинт `/metrics`.
- Трассировка времени выполнения гостевого WASM-кода через Wasmtime Epoch Deadlines.

## 3. Управление аппаратными лимитами песочницы (Resource Quotas)

- **Memory Quota**: жесткий лимит страниц памяти WebAssembly (1 страница = 64 KB). При превышении Wasmtime генерирует `MemoryOutOfBounds` Trap, изолируя сбой.
- **CPU Epoch Interruption**: планировщик ядра инкрементирует счетчик эпох каждые 100 мс, предотвращая блокировку потоков зависшим гостевым кодом.
- **Single-Writer Concurrency**: блокировки SQLite исключены на уровне архитектуры благодаря выделенному пулу с 1 writer-соединением и очереди MPSC.
