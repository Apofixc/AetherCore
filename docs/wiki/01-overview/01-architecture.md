# 🏛️ Архитектура Next-Gen Universal Core Platform

## 1. Введение и концепция Universal Microkernel

Платформа **Next-Gen Universal Core Platform** представляет собой высокопроизводительное, безопасное и расширяемое микроядро на Rust с модульной архитектурой на базе WASM (WebAssembly Component Model / Wasmtime) и Axum HTTP/WS шлюза.

> [!IMPORTANT]
> **Domain-Agnostic парадигма:**
> Ядро платформы полностью отделено от конкретной предметной области (мониторинг, автоматизация, IoT, медиасервисы). Ядро выполняет роль универсального хоста: предоставляет изолированную песочницу исполнения, шину сообщений, базу данных, подсистему авторизации, планировщик и микрофронтенд-оболочку.

## 3. Ключевые архитектурные подсистемы

### 3.1. Двойной режим работы (Dual-Mode Execution)
Бинарный файл `nms` адаптирует поведение в зависимости от аргументов командной строки:
1. **Headless Daemon / Server (`nms --server --port 8080`)**:
   - Работа в фоновом режиме без графического окна (Linux/Docker/Server).
   - Axum HTTP/WS сервер слушает на `0.0.0.0` / `127.0.0.1`.
   - Аутентификация через JWT токены в заголовках `Authorization: Bearer <token>`.
2. **Desktop App (Tauri Desktop)**:
   - Инициализирует WebView окно.
   - Поднимает локальный бэкенд на loopback `127.0.0.1:{random_port}` с одноразовым сессионным Bearer-токеном.

### 3.2. База данных: SQLite WAL Single-Writer / Multi-Reader
Для исключения конфликтов конкурентного доступа при круглосуточной записи телеметрии 24/7 реализовано строгое разделение пулов соединений:
- **Single-Writer Pool**: ровно 1 соединение на запись с обязательными прагмами `PRAGMA journal_mode = WAL;`, `PRAGMA busy_timeout = 5000;`, `PRAGMA synchronous = NORMAL;`.
- **Multi-Reader Pool**: масштабируемый пул неблокирующих соединений на чтение.

### 3.3. Гибридная шина событий (Event Bus)
- **Live Ephemeral Bus (`tokio::sync::broadcast`)**: кольцевой буфер на 1024 сообщений для высокоскоростной передачи тиков телеметрии и реалтайм-графиков на фронтенд.
- **Reliable Event Journal (`tokio::sync::mpsc` + SQLite WAL)**: очередь гарантированной доставки для системных событий, алертов и аудита.

### 3.4. Изолированное хранилище состояния плагинов (KV Store)
Каждый модуль получает изолированное Key-Value хранилище с автоматическим пространством имен `module:{id}:{key}`. Доступ к чужим ключам блокируется на уровне ядра.

### 3.5. Безопасность и Zero-Unpack загрузка плагинов
Плагины хранятся в каталоге `modules/` в виде единых архивов `.nms-plugin` (ZIP). Ядро считывает манифест `manifest.yaml`, байткод `backend.wasm`, локали и статические файлы фронтенда напрямую из архива в память без распаковки на диск сервера. Перед инициализацией проверяется цифровая подпись Ed25519.
