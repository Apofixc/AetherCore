# Уведомления, системное управление и Вики (Notifications & System API)

Документ описывает REST API эндпоинты управления уведомлениями, тихими часами, бэкапом базы данных SQLite `nms.db`, активными сессиями клиентов и Вики документацией в `nms-core`.

---

## 1. Назначение и общая концепция
Данный раздел включает REST API роутеры для работы с оперативными уведомлениями, квитированием аварий, управлением активными пользовательскими сессиями, резервным копированием базы данных и встроенной базой знаний (Вики).

---

## 2. Доступные REST API эндпоинты и элементы управления

### Система уведомлений (`/api/v1/notifications/`)
* **`GET /api/v1/notifications`**: Получение списка уведомлений с поддержкой пагинации (`limit`, `offset`) и фильтрацией по `unread_only`, `severity`, `category`, `search`.
* **`POST /api/v1/notifications/{id}/read`**: Отметка конкретного уведомления как прочитанного.
* **`POST /api/v1/notifications/read-all`**: Отметка всех уведомлений адресата как прочитанных.
* **`POST /api/v1/notifications/{id}/acknowledge`**: Квитирование аварийного алерта.
* **`GET /api/v1/notifications/preferences` & `PUT`**: Получение и обновление настроек тихих часов и заглушения.
* **`GET /api/v1/notifications/export`**: Экспорт сохраненных логов уведомлений в форматах CSV и JSON.

### Системное управление и Вики (`/api/v1/system/`)
* **`GET /api/v1/system/backup`**: Выгрузка бинарной резервной копии базы данных SQLite `nms.db` (`application/x-sqlite3`).
* **`GET /api/v1/system/sessions`**: Получение списка всех активных сессий пользователей.
* **`POST /api/v1/system/sessions/terminate-all`**: Принудительное аннулирование всех активных сессий пользователей.
* **`GET /api/v1/system/docs/wiki/tree`**: Получение дерева категорий и статей встроенной Вики.
* **`GET /api/v1/system/docs/wiki/article`**: Выдача содержимого конкретной Markdown-статьи по `path`.

### История событий (`/api/v1/events/`)
* **`GET /api/v1/events/history`**: Извлечение сохраненных журналов событий из БД по `from_seq_id` и `topic`.

---

## 3. Логика работы и связь с бэкендом (Axum + Rust Core)
1. **Дедупликация и квитирование**: Движок `NotificationEngine` автоматически группирует частые однотипные события за последние 60 секунд.
2. **Экспорт**: Формирует CSV с экранированием запятых или форматированный JSON.
3. **Резервное копирование**: Прямое безопасное считывание файла `nms.db` в асинхронном потоке `tokio::fs::read`.

---

## 4. Пользовательские сценарии (User Workflows)

### Сценарий 1: Просмотр и квитирование аварий
1. Клиент делает запрос `GET /api/v1/notifications?unread_only=true&severity=Error`.
2. После обработки аварии на объекте инженер отправляет `POST /api/v1/notifications/{id}/acknowledge`.

### Сценарий 2: Скачивание резервной копии системы
1. Администратор вызывает `GET /api/v1/system/backup`.
2. Сервер отдает готовый к восстановлению `.db` файл с именем вида `nms-backup-YYYYMMDD-HHMMSS.db`.
