# 🔐 Модель безопасности и ролевой доступ (RBAC)

## 1. Концепция безопасности ядра

Платформа использует многоуровневую модель безопасности:
1. **Аутентификация учетных записей**: хэширование паролей алгоритмом **Argon2id** (OWASP standard).
2. **Сессионная авторизация**: криптографические **JWT** токены (HMAC/Ed25519) с временем жизни и гранулярными правами доступа.
3. **Ролевая модель доступа (RBAC Matrix)**: разграничение прав пользователей на уровне ролей и индивидуальных прав.
4. **Изоляция песочницы плагинов (Wasmtime Capabilities)**: плагины работают в закрытом окружении без прямого доступа к сокетам ОС и хостовой ФС.
5. **Защита от спуфинга топиков**: плагин может публиковать события только в пространстве имен `{plugin_id}.*`.

## 2. Матрица системных ролей и прав доступа

### Стандартные роли (Built-in Roles):
- **`admin`**: полный административный доступ ко всем операциям и системным настройкам.
- **`operator`**: оператор мониторинга, управления устройствами и настройки модулей.
- **`viewer`**: режим только для чтения (просмотр дашбордов, статусов и журналов).

### Системные права доступа (Permissions):

| Идентификатор права | Название | Категория | Описание |
| :--- | :--- | :--- | :--- |
| `system.view` | Просмотр системы | `System` | Доступ к чтению статуса ядра, метрик и информации о сервере |
| `system.manage` | Управление системой | `System` | Изменение системных настроек, сброс кэша, перезагрузка |
| `users.view` | Просмотр пользователей | `Users` | Просмотр списка учетных записей и ролей |
| `users.manage` | Управление пользователями | `Users` | Создание, редактирование, блокировка пользователей и смена паролей |
| `modules.view` | Просмотр модулей | `Modules` | Просмотр списка установленных плагинов и их манифестов |
| `modules.manage` | Управление модулями | `Modules` | Установка, включение, выключение и сохранение настроек плагинов |
| `events.view` | Просмотр событий | `Events` | Чтение персистентного журнала системных событий |

## 3. Аудит действий пользователей (Audit Log)

Каждое критическое действие (вход в систему, создание/удаление пользователей, изменение конфигурации ядра или модулей) автоматически регистрируется в таблице `audit_logs` базы данных SQLite.

Запись аудита содержит:
- `user_id`, `username` — инициатор действия
- `action` — тип операции (например, `users.create`, `modules.enable`, `auth.login`)
- `resource` — целевой ресурс (`users/{id}`, `modules/{id}/config`)
- `status` — статус результата (`success`, `failed`)
- `ip_address` — IP-адрес клиента
- `created_at` — точный таймстамп действия
