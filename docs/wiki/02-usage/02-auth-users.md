# Модуль авторизации, пользователей и безопасности (Auth & Users)

Документ описывает подсистему безопасности, генерации JWT токенов, аутентификации 2FA/TOTP, разграничения прав RBAC и REST API эндпоинты в `nms-core`.

---

## 1. Назначение и общая концепция
Подсистема Auth & Users обеспечивает безопасную аутентификацию клиентов по логину и паролю (Argon2id), обработку 2FA/TOTP (RFC 6238), выпуск и валидацию JWT токенов, а также предоставление REST API для управления пользователями и их ролями RBAC.

---

## 2. Доступные REST API эндпоинты и элементы управления

### Аутентификация (`/api/v1/auth/`)
* **`POST /api/v1/auth/login`**: Вход в систему по `username`, `password` и опциональному `totp_code`. Возвращает `access_token` и `refresh_token`.
* **`POST /api/v1/auth/refresh`**: Обновление токена доступа по действующему `refresh_token`.
* **`POST /api/v1/auth/2fa/setup`**: Генерация 160-битного Base32 секрета 2FA и нативного SVG QR-кода (`generate_qr_svg`).

### Управление пользователями (`/api/v1/users/`)
* **`GET /api/v1/users`**: Получение списка всех пользователей и их ролей.
* **`POST /api/v1/users`**: Создание нового пользователя с хэшированием пароля Argon2id.
* **`PUT /api/v1/users/{id}`**: Обновление ФИО, email, роли или статуса активности.
* **`DELETE /api/v1/users/{id}`**: Удаление пользователя из базы данных SQLite.

---

## 3. Логика работы и связь с бэкендом (Axum + Rust Core)

1. **Защита от брутфорса (Rate Limiting)**:
   - Эндпоинт `login` автоматически использует `RateLimiter` (`login:{username}`). При превышении 5 попыток за 60 секунд возвращается HTTP 403 `PermissionDenied`.

2. **Хэширование паролей (Argon2id)**:
   - Пароли хэшируются с использованием OWASP Argon2id (`hash_password`, `verify_password`).

3. **Многофакторная аутентификация 2FA / TOTP (RFC 6238)**:
   - Расчет и проверка 6-значных OTP-кодов (`verify_totp_code`) с временным окном рассинхронизации ±30 секунд.
   - Генерация SVG QR-кодов без внешних JS-компиляторов (`generate_qr_svg`).

4. **Шифрование данных at-rest (`crypto.rs`)**:
   - Шифрование секретов через AES-256-GCM + HKDF-SHA256 (префикс `enc:v1:`).

## 4. Пользовательские сценарии (User Workflows)

### Сценарий 1: Авторизация пользователя
1. Клиент отправляет запрос `POST /api/v1/auth/login` с логином и паролем.
2. Бэкенд проверяет RateLimiter, извлекает запись пользователя из SQLite и сверяет хэш Argon2id.
3. В случае успеха возвращается пара токенов `access_token` (24 часа) и `refresh_token` (7 дней).

### Сценарий 2: Подключение 2FA
1. Пользователь вызывает `POST /api/v1/auth/2fa/setup`.
2. Бэкенд генерирует секрет и отдает готовый SVG-код для сканирования приложением (Google Authenticator, YubiKey).
