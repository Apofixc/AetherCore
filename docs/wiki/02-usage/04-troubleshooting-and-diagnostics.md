# 🛠️ Диагностика, Логирование и Troubleshooting

## 1. Управление логированием (`RUST_LOG`)

Ядро платформы использует структурированную систему трассировки `tracing`. Уровень детализации логов настраивается через переменную окружения `RUST_LOG`:

```bash
# Рекомендуемый уровень для продакшена (информационные сообщения ядра и предупреждения)
export RUST_LOG="info,nms_core=debug"
./target/release/nms --server

# Детальная отладка всех подсистем (включая SQL-запросы и события шины)
export RUST_LOG="debug,sqlx=info,tokio=warn"
./target/release/nms --server --dev

# Максимальный уровень трассировки с таймстампами
export RUST_LOG="trace"
./target/release/nms --server
```

---

## 2. Аварийный запуск в безопасном режиме (`--safe-mode`)

Если один из установленных плагинов поврежден, вызывает циклические паники или блокирует старт системы, запустите платформу в безопасном режиме:

```bash
./target/release/nms --server --safe-mode --port 8080
```

> [!NOTE]
> В режиме `--safe-mode` ядро стартует базу данных SQLite, сервисы аутентификации, RBAC и веб-интерфейс, но **полностью пропускает загрузку сторонних плагинов** из каталога `modules/`. Администратор может войти в панель управления, отключить проблемный плагин или обновить его конфигурацию.

## 3. Решение типовых проблем (Troubleshooting Guide)

### Проблема 1: Ошибка `database is locked` при высокой нагрузке
- **Причина**: Попытка одновременной записи из нескольких потоков без соблюдения Single-Writer архитектуры.
- **Решение**: Убедитесь, что в конфигурации SQLite включен WAL-режим (`PRAGMA journal_mode=WAL;`), а параметр `busy_timeout_ms` в `config.toml` установлен не менее `5000` мс. Для записи всегда используйте `db.writer()`.

### Проблема 2: Плагин завершается с ошибкой `PLUGIN_TIMEOUT`
- **Причина**: Гостевой код WASM выполняет тяжелые синхронные вычисления или блокирующий цикл, превышая лимит времени (CPU Epoch Interruption).
- **Решение**: Увеличьте `execution_timeout_sec` в `config.toml` или оптимизируйте алгоритм в гостевом коде (разбивайте итерации через таймеры `tick`).

### Проблема 3: Не удается подключиться по WebSocket (`401 Unauthorized`)
- **Причина**: Отсутствует или истек срок действия JWT токена в параметрах запроса.
- **Решение**: Передавайте актуальный токен в query-параметре: `ws://127.0.0.1:8080/ws/events?token=<jwt_token>`.

### Проблема 4: Сброс пароля учетной записи администратора
- **Решение**: Если доступ утерян, можно переинициализировать дефолтного администратора через CLI:
  ```bash
  # Очистить таблицу пользователей в тестовой БД или удалить файл базы данных (при первом старте создастся admin/admin)
  rm -f data/nms.db*
  ./target/release/nms --server
  ```
