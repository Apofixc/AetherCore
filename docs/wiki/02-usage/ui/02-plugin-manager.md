# 🧩 Менеджер плагинов в интерфейсе (Plugin Manager UI)

## 1. Назначение экрана

Экран **Менеджер модулей** (`/modules`) доступен пользователям с правом `modules.view` и позволяет:
- Просматривать список всех обнаруженных ядром пакетов `.nms-plugin`.
- Видеть статус активности (Включен / Выключен), версию, автора и запрашиваемые системные привилегии (`capabilities`).
- Включать и выключать модули в один клик без перезапуска сервера (требуется право `modules.manage`).
- Настраивать параметры модуля через автоматически сгенерированные формы (Schema-driven forms).

---

## 2. Автоматическая генерация форм настроек (Schema-Driven Forms)

Если в `manifest.yaml` модуля присутствует секция `config_schema`, интерфейс автоматически строит модальное окно настроек:

- `type: "integer"`, `minimum`, `maximum` ──► Числовые поля ввода (Spinbox / Slider)
- `type: "string"` ──► Текстовые поля или выпадающие списки (Select)
- `type: "boolean"` ──► Переключатели (Toggle Switch)
- `required: [...]` ──► Валидация обязательных полей на клиенте перед отправкой `PUT /api/v1/modules/{id}/config`

---

## 3. Пользовательские сценарии (Workflows)

1. **Включение нового плагина**:
   - Администратор копирует `.nms-plugin` архив в директорию `modules/`.
   - В интерфейсе появляется карточка модуля с кнопкой «Включить».
   - При нажатии отправляется `POST /api/v1/modules/{id}/enable`, ядро активирует хук `on_enable`, регистрирует маршруты UI и меню.
2. **Изменение параметров работы**:
   - Нажатие на кнопку «Настройки» открывает модальное окно.
   - Пользователь вводит новые значения и нажимает «Сохранить».
   - Ядро валидирует данные по JSON Schema, сохраняет в `kv_store` и публикует событие `{module_id}.config_changed`.
