# Модуль ограничения частоты запросов (RateLimiter)

Документ описывает подсистему скользящего ограничения частоты запросов (In-memory Sliding Window Rate Limiter) в `nms-core`.

---

## 🏛️ Назначение и принцип работы

Модуль `RateLimiter` предназначен для защиты системы и ее REST/WebSocket API от DoS-атак, брутфорса паролей и чрезмерной нагрузки со стороны отдельных клиентов.

* **Алгоритм**: Скользящее временное окно (Sliding Window).
* **Потокобезопасность**: Защищён через `Arc<Mutex<HashMap<String, Vec<Instant>>>>`.
* **Авто-очистка**: При каждом обращении автоматически удаляются устаревшие метки времени, выходящие за пределы текущего временного окна `window_seconds`.

---

## ⚙️ Публичный интерфейс `RateLimiter`

### 1. `RateLimiter::new()`
Создаёт новый экземпляр `RateLimiter`.

### 2. `is_rate_limited(&self, key: &str, max_requests: usize, window_seconds: u64) -> bool`
Проверяет, не превысил ли клиент с ключом `key` лимит в `max_requests` за последние `window_seconds` секунд.
* **`key`**: Уникальный составной ключ клиента (например `192.168.1.10:admin:login`).
* **`max_requests`**: Максимальное число разрешенных запросов.
* **`window_seconds`**: Размер окна в секундах.
* **Возвращает**: `true`, если лимит превышен (запрос следует отклонить с HTTP 429), и `false`, если запрос разрешён.

### 3. `clear(&self)`
Очищает внутреннее состояние и сбрасывает все счётчики.

---

## 💡 Пример использования в Rust

```rust
use nms_core::RateLimiter;
use std::time::Duration;

let limiter = RateLimiter::new();
let client_key = "192.168.1.50:login";

// Лимит: не более 5 попыток входа за 60 секунд
if limiter.is_rate_limited(client_key, 5, 60) {
    println!("Превышен лимит запросов. Доступ временно ограничен.");
} else {
    println!("Запрос успешно обработан.");
}
```
