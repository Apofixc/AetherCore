# 🔍 Отладка, Профилирование и Анализ паник WASM-модулей

## 1. Изоляция сбоев и перехват паник (Wasmtime Traps)

В отличие от Python, где необработанное исключение в модуле могло привести к утечке памяти или падению всего сервиса, в платформе Next-Gen на Rust каждый плагин изолирован в песочнице Wasmtime:

1. **Паника в коде плагина (`panic!`)**:
   - Wasmtime мгновенно ловит `Trap` (unreachable code execution).
   - Стек вызова паники изолируется и логируется ядром с тегом `[PLUGIN_CRASH: <id>]`.
   - Ядро сохраняет стабильность, переводит плагин в статус `Faulted` и продолжает обслуживать остальные запросы.

2. **Превышение лимита памяти (Out-Of-Memory)**:
   - Лимит `memory_limit_mb` предотвращает выделение памяти сверх квоты. Плагин получает `MemoryOutOfBounds Trap`.

3. **Зацикливание (CPU Epoch Deadlock)**:
   - Если гостевая функция не завершается за отведенный таймаут (по умолчанию 5 секунд), планировщик ядра прерывает исполнение с кодом `PLUGIN_TIMEOUT`.

## 2. Локальная отладка модуля в режиме `--dev`

В режиме разработки `--dev`:
- Поддерживается загрузка неподписанных модулей напрямую из папок.
- Оболочка Vue Shell включает поддержку компиляции SFC компонентов на лету через `vue3-sfc-loader`.
- Включен подробный вывод трассировки `RUST_LOG=debug`.
