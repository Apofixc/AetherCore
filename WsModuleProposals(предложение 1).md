# Предложения по расширению модуля WebSocket (`ws`)

> **Модуль:** `crates/aethercore-server/src/ws/mod.rs`
> **Статус:** черновик / на обсуждение

## Текущее состояние

Реализовано:
- Подключение `/ws/events?token=...&topics=...&retained=true`
- Динамические подписки: `subscribe` / `unsubscribe` / `ping`
- Retained-состояния при подключении и подписке
- Проброс бинарных кадров телеметрии
- RAII-очистка подписки на шине при разрыве соединения

- [ ] 2.2 Фикс утечки задач

### Приоритет 2 — интерактивность (ближайший релиз)
- [ ] 3.1 Публикация из WS-клиента

### Приоритет 3 — устойчивость под нагрузкой телеметрии
- [ ] 2.5 Backpressure-политика

### Отложенные (по мере надобности)
- 2.3 Session resume/replay — когда появятся жалобы на потерю данных после обрывов сети
- 3.2 RPC over WS — когда появятся реальные двунаправленные сценарии
- 4.1 Реестр соединений — при росте числа пользователей

## Обоснование приоритизации

Архитектура проекта (дашборды реального времени, телеметрия устройств, плагины,
RBAC) определяет порядок:

1. **Приоритет 1** устраняет две реальные проблемы (анонимный доступ к потоку
   событий, возможная утечка токенов/соединений) при минимальных трудозатратах.
2. **Приоритет 2** превращает шлюз из однонаправленного «телевизора» в полноценный
   транспорт: команды устройствам без REST-roundtrip + отсечение low-priority шума.
3. **Приоритет 3** критичен для сценария высокочастотной телеметрии NMS: без него
   один «медленный» клиент деградирует рассылку для всех.
